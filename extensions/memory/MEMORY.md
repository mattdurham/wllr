# Memory Extension — Engram Design

A persistent, searchable memory store for wllr conversations. Memories are stored as engrams — discrete units with semantic embeddings, contextual attributes, and similarity-based retrieval.

---

## Storage

Single SQLite database at `~/.wllr/memory.db` using `modernc.org/sqlite` (pure Go, no CGo). The extension runs as a **native Go tool** on the host side, not inside WASM.

### Schema

```sql
CREATE TABLE engrams (
    id          TEXT PRIMARY KEY,           -- UUID v4
    content     TEXT NOT NULL,              -- the memory text
    embedding   TEXT NOT NULL,              -- JSON float array (semantic vector)
    summary     TEXT,                       -- optional short summary for display

    -- Context attributes
    cwd         TEXT,                       -- working directory at creation time
    repo        TEXT,                       -- git repo name (basename of remote origin)
    user        TEXT,                       -- git user.name or $USER

    -- Metadata
    session_id  TEXT,                       -- wllr session ID
    tags        TEXT DEFAULT '[]',          -- JSON string array
    importance  REAL DEFAULT 0.5,           -- 0.0–1.0, user-set or inferred
    access_count INTEGER DEFAULT 0,         -- retrieval count (for relevance decay)
    created_at  INTEGER NOT NULL,           -- Unix nanoseconds
    updated_at  INTEGER NOT NULL
);

CREATE INDEX idx_engrams_repo ON engrams(repo);
CREATE INDEX idx_engrams_cwd  ON engrams(cwd);
CREATE INDEX idx_engrams_user ON engrams(user);
```

### Embedding strategy

Embeddings are 384-dimension float vectors generated by calling the Anthropic API (`text-embedding-ada-002` compatible endpoint, or a local alternative). The extension stores them as JSON arrays. Cosine similarity is computed in Go at query time — no sqlite-vec dependency needed.

For offline / no-embedding mode, the extension falls back to TF-IDF bag-of-words vectors so search still works without an API call.

## Tools registered

### `memory_store`

Store a new engram. Embedding is generated automatically.

```json
{
  "type": "object",
  "properties": {
    "content":    { "type": "string", "description": "The memory to store" },
    "tags":       { "type": "array",  "items": { "type": "string" }, "description": "Optional tags" },
    "importance": { "type": "number", "description": "0.0–1.0 importance weight (default 0.5)" }
  },
  "required": ["content"]
}
```

Context attributes (`cwd`, `repo`, `user`, `session_id`) are captured automatically from the environment at store time.

Returns: `{ "id": "...", "stored": true }`

---

### `memory_search`

Search engrams by similarity and/or attributes. Returns top-k results ranked by a combined score.

```json
{
  "type": "object",
  "properties": {
    "query":      { "type": "string",  "description": "Semantic search query" },
    "repo":       { "type": "string",  "description": "Filter by repo name" },
    "cwd":        { "type": "string",  "description": "Filter by working directory" },
    "user":       { "type": "string",  "description": "Filter by user" },
    "tags":       { "type": "array",   "items": { "type": "string" }, "description": "Filter: must match all tags" },
    "limit":      { "type": "integer", "description": "Max results (default 10)" },
    "min_score":  { "type": "number",  "description": "Minimum similarity score 0–1 (default 0.3)" }
  }
}
```

**Ranking formula:**

```
score = (similarity_weight * cosine_similarity)
      + (importance_weight * engram.importance)
      + (recency_weight   * recency_decay(engram.created_at))
```

Default weights: similarity=0.6, importance=0.25, recency=0.15.

Returns: array of `{ id, content, summary, score, cwd, repo, user, tags, created_at }`

---

### `memory_get`

Retrieve a single engram by ID.

```json
{ "type": "object", "properties": { "id": { "type": "string" } }, "required": ["id"] }
```

Side effect: increments `access_count`.

---

### `memory_update`

Update content, tags, or importance of an existing engram. Re-generates embedding if content changes.

```json
{
  "type": "object",
  "properties": {
    "id":         { "type": "string" },
    "content":    { "type": "string" },
    "tags":       { "type": "array", "items": { "type": "string" } },
    "importance": { "type": "number" }
  },
  "required": ["id"]
}
```

---

### `memory_delete`

Delete an engram by ID.

```json
{ "type": "object", "properties": { "id": { "type": "string" } }, "required": ["id"] }
```

---

### `memory_export`

Export engrams to a file (JSON or Markdown).

```json
{
  "type": "object",
  "properties": {
    "path":   { "type": "string", "description": "Output file path" },
    "format": { "type": "string", "enum": ["json", "markdown"], "description": "Default: json" },
    "repo":   { "type": "string", "description": "Filter by repo (optional)" },
    "tags":   { "type": "array",  "items": { "type": "string" }, "description": "Filter by tags (optional)" }
  },
  "required": ["path"]
}
```

**JSON export:** array of full engram objects (without embedding vectors — those are large and not human-readable).

**Markdown export:**
```markdown

memory, so concurrent _on_event calls must be serialized with callMu...
```

## Implementation layout

```
extensions/memory/
├── MEMORY.md           ← this file
├── main.go             ← native tool registration (package main, no WASM build tag)
├── db.go               ← SQLite schema, open/migrate
├── engram.go           ← store, search, get, update, delete
├── embed.go            ← embedding generation + TF-IDF fallback
└── export.go           ← JSON and Markdown export
```

The extension is registered in `cmd/main.go` via `h.RegisterNativeTool` — no WASM build required. `modernc.org/sqlite` compiles to native Go on all platforms.

## Session integration

The memory extension subscribes to `before_agent_start` to capture context attributes automatically:

```go
OnBeforeAgentStart(func(prompt string) {
    cwd, _  = os.Getwd()
    repo, _ = gitRepoName()  // git remote origin basename
    user, _ = gitUserName()  // git config user.name || $USER
})
```

This ensures every stored memory has accurate `cwd`, `repo`, and `user` without the LLM having to specify them.

## Search example

```
User: /memory search what do we know about the extension host concurrency?

Agent calls memory_search({
  "query": "extension host concurrency WASM",
  "repo":  "wllr"
})

Returns:
  [0.91] WASM extensions share linear memory — callMu serializes _on_event calls
  [0.84] Native tools bypass WASM and are goroutine-safe
  [0.72] EventBeforeToolCall fires before both native and WASM tools
```
