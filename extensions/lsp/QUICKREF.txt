LSP EXTENSION QUICK REFERENCE

Primary agent workflows:
  diagnostics, linting, code navigation, references, refactor preview
  Use lsp_capabilities near the start of repo/code work unless this session
  already knows available backends and output contracts.
  Use LSP navigation/reference tools before broad grep/rg/find or large
  read_file sweeps when the task is about code structure.

Tools and input:
  lsp_capabilities
    {}

  lsp_diagnostics
    {"file":"path/to/file.go"}

  lsp_lint
    {"path":"."}
    {"file":"path/to/file.go"}

  lsp_symbols
    {"file":"path/to/file.go"}

  lsp_definition
    {"symbol":"Name","path":"."}

  lsp_references
    {"symbol":"Name","path":"."}

  lsp_refactor_preview
    {"symbol":"OldName","new_name":"NewName","path":"."}

Output:
  Every tool returns a JSON string. Common fields:
    ok        true when the tool found usable information or validation passed
    kind      diagnostics, lint, symbols, definition, references, refactor_preview
    target    file or directory searched
    command   command used for diagnostics/linting, when applicable
    pattern   search pattern used for navigation/refactor tools
    output    diagnostic/lint output
    matches   file:line matches for navigation/refactor tools
    error     execution error when no usable output was found

Notes:
  lsp_refactor_preview never edits files.
  Apply edits with normal file-editing tools after reviewing matches.
  Use lsp_capabilities to inspect supported languages and backend commands.
  Use lsp_diagnostics or lsp_lint after source edits before raw shell tests when
  a backend is available.
